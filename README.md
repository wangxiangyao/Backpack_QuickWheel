# 🎒 Backpack QuickWheel - 行军包配件轮盘系统

一个为《逃离鸭科夫》设计的增强型背包配件管理模组，提供直观的轮盘选择界面和便捷的配件交互功能。

## 📋 当前版本：v1.2.0 "配件交互增强版"

**发布日期：** 2025年11月4日
**游戏版本：** 适用于最新的《逃离鸭科夫》

---

## 🏗️ 核心架构：src 模块详解

### 📁 **ModBehaviour.cs** - 模组主入口
模组的**核心控制器**和**生命周期管理器**：
- **统一初始化中心**：管理所有子系统的启动顺序和依赖关系
- **事件协调器**：处理关卡初始化、玩家状态变化等游戏事件
- **Harmony补丁管理**：集成运行时修改框架，确保所有补丁正确应用
- **跨场景持久化**：使用`DontDestroyOnLoad`确保模组在场景切换时不丢失状态

**核心设计理念**：通过程序入口点初始化(`InitializeShortcutSystemAtEntryPoint`)确保不会错过任何背包装备事件，解决了模组启动时序依赖的复杂问题。

---

### 📁 **AttachmentSystem/** - 配件系统核心

#### **AttachmentManager.cs** - 配件物品创建器
- **动态物品生成**：运行时创建10余种功能性背包配件（网兜、水壶袋、战术包等）
- **Tag系统集成**：管理游戏内置Tag和模组自定义Tag的映射关系
- **物品属性配置**：通过`AttachmentItemConfig`配置配件的容量、重量、插槽限制等属性

#### **SlotConfig.cs** - 插槽配置系统
- **兼容性矩阵**：定义不同配件可装备的插槽类型
- **容量管理**：控制每个配件的最大容纳物品数量和类型限制

**开发难点**：配件物品需要与游戏复杂的物品系统和Tag系统完美集成，同时保持与原有背包系统的兼容性。

---

### 📁 **BackpackSystem/** - 背包修改系统

#### **BackpackModifier.cs** - 背包属性修改器
- **动态背包改造**：为现有背包添加新的配件插槽
- **属性平衡调整**：确保新增配件不影响游戏平衡性
- **向后兼容**：保证已有背包物品不受影响

**设计挑战**：需要在保持游戏原有体验的基础上，无缝扩展背包功能而不破坏存档兼容性。

---

### 📁 **ShortcutSystem/** - 快捷键轮盘系统

#### **ItemWheelSelector.cs** - 轮盘UI核心
- **九宫格布局**：以鼠标为中心的环形轮盘界面
- **双重操作模式**：长按使用物品 vs 点击切换选中
- **动态内容收集**：实时从背包配件中收集可用物品

#### **BackpackShortcutManager.cs** - 背包状态管理
- **事件驱动架构**：监听背包装备/卸载事件，自动更新轮盘内容
- **物品分类系统**：通过`ItemCategorizer`将物品按医疗、针剂、食物等分类
- **状态同步机制**：确保UI状态与实际背包状态实时同步

#### **输入处理子系统**
- **InputInterceptor.cs**：全局输入拦截，捕获轮盘快捷键
- **WheelLayoutManager.cs**：轮盘布局算法和视觉反馈
- **ItemUsageHandler.cs**：物品使用逻辑，支持快捷操作

**技术亮点**：实现了复杂的三层事件订阅架构（装备事件→状态管理→UI更新），完美解决了拖拽物品引用获取的技术难题。

## ⚠️ 开发中的重大挑战

### 🎯 **配件详情UI自动关闭问题**（严重程度：中等）
**问题现象**：在物品详情页面点击第二排槽位中的配件时，详情会在约0.3秒后自动关闭。

**根本原因**：
- **架构限制**：官方缺乏稳定的详情页面跳转API
- **UI交互区域限制**：第二排配件详情UI较小，鼠标容易落在有效交互区域外
- **状态管理复杂性**：`NotifyUnselected()`→`ContextMenu.Hide()`→`SelectedItemDisplay`为null的连锁反应

**尝试的解决方案**：
1. **四层保护系统** - 失败，无法解决UI区域限制
2. **延迟保护机制** - 部分有效，但仍被绕过
3. **交互区域扩展** - 理论正确但实现复杂
4. **KontextMenu控制** - 可延迟关闭但非根本解决

**结论**：此问题需要官方提供稳定API才能彻底解决，目前作为已知问题记录。

### 🔧 **系统初始化时序依赖问题**
**挑战**：模组多个子系统存在复杂的启动依赖关系，需要在正确的时机初始化。

**解决方案**：
- **程序入口点初始化**：在`Awake()`中尽早创建关键组件
- **混合初始化策略**：结合程序入口点和关卡初始化两个时机
- **状态检查机制**：主动检查当前背包状态，防止错过装备事件

### 🎭 **反射依赖的维护性问题**
**挑战**：大量使用反射访问游戏私有成员，版本兼容性风险高。

**缓解策略**：
- **异常处理**：完善的try-catch机制和错误恢复
- **版本检测**：运行时检测游戏版本，适配不同API
- **降级处理**：关键功能失败时的优雅降级

### 🚀 **性能优化挑战**
**拖拽性能问题**：直接拖拽物品时存在轻微卡顿
- **缓存优化**：通过`SlotIndicatorCacheManager`缓存UI组件
- **按需加载**：只在需要时创建轮盘UI
- **内存管理**：优化组件生命周期和垃圾回收

## 🎮 使用方法

### 基础操作
1. **装备背包配件**：将模组新增的配件装备到背包上
2. **打开轮盘**：长按快捷键（默认配置）显示九宫格轮盘
3. **选择物品**：
   - 长按时悬停物品，松开直接使用
   - 点击物品切换选中状态
