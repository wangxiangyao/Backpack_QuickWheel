# 已知问题 (Known Issues)
*适用于《逃离鸭科夫》v1.2.0版本*

## 疑难杂症：第二排配件详情UI自动关闭问题

### 问题描述
在物品详情页面中，点击第二排槽位中的配件时：
1. 配件详情会正确显示
2. 但约0.3秒后UI会自动关闭
3. 第一排槽位工作正常，只有第二排受影响

### 根本原因分析
**核心问题：官方缺乏详情页面的稳定跳转API**

1. **架构限制**：官方没有提供直接的详情页面跳转功能，导致我们需要通过销毁/重建来实现详情切换

2. **UI交互机制**：
   - 详情页面内部有 `ItemSlotCollectionDisplay` 组件管理插槽交互
   - `entriesParent` 定义了有效的鼠标交互区域
   - 第二排配件的详情UI较小，鼠标容易落在 `entriesParent` 区域外
   - `KontextMenu` 检测到鼠标在UI外部会自动关闭

3. **状态管理复杂性**：
   - `ItemUIUtilities.Select()` 会触发 `NotifyUnselected()`
   - `NotifyUnselected()` 调用 `ContextMenu.Hide()` 清空 `ItemDisplay.Target`
   - `SelectedItemDisplay` getter依赖 `Target`，`Target` 为null时返回null
   - 造成详情UI失去选中状态而关闭

### 尝试的解决方案
1. **四层保护系统** - 失败，无法从根本上解决UI区域限制问题
2. **延迟保护机制** - 部分有效，但仍被UI交互区域限制绕过
3. **交互区域扩展** - 理论上正确，但实现复杂且效果不稳定
4. **KontextMenu控制** - 可以延迟关闭，但无法解决根本的交互区域问题

### 技术限制
- **反射依赖**：所有方案都需要通过反射访问私有字段，维护困难
- **时序问题**：UI组件的生命周期和事件顺序复杂，难以精确控制
- **兼容性风险**：修改核心UI逻辑可能影响其他功能

### 结论
此问题需要官方提供稳定的详情页面跳转API才能从根本上解决。目前的临时方案都存在维护性和稳定性问题，建议作为已知问题记录，等待官方API支持。

### 影响范围
- **影响功能**：配件详情页面的稳定性
- **影响用户**：查看背包配件详情的用户
- **严重程度**：中等（不影响核心功能，但影响用户体验）
