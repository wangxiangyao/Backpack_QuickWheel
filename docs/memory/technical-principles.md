# 源码驱动开发原则 - 详细版

## 🔥 核心原则阐述

### 1. 源码驱动开发原则 【铁律】

**为什么必须源码驱动？**
- Unity系统参数含义经常与直觉相反
- 官方API性能和兼容性最优
- 避免重复造轮子和隐藏陷阱

**实施标准流程**:
```
问题复现 → 查找GameSource/Duckov/源码 → 分析参数含义 →
基于源码实现 → 验证效果 → 记录最佳实践
```

**绝对禁止的行为**:
- ❌ 基于参数名称猜测功能
- ❌ 基于其他游戏经验实现功能
- ❌ 不看源码就实现复杂功能
- ❌ 忽略官方API而自定义实现

### 2. 官方API优先原则

**优先级排序**:
1. **官方API** - 游戏提供的标准接口
2. **官方模式** - 源码中推荐的做法
3. **Coop-Mod参考** - 已验证的第三方实现
4. **自定义实现** - 仅在前三者都不可用时

**官方API优势**:
- 性能最优（底层优化）
- 兼容性最好（跟随游戏版本）
- 维护成本最低
- 避免重复工作

### 3. 简洁性原则

**复杂度警示**:
- 协程 > 简单方法调用
- 反射 > 直接访问
- 多层抽象 > 简单实现
- 自定义系统 > 官方API

**简洁性检查清单**:
- [ ] 是否有更简单的官方API？
- [ ] 是否真的需要协程？
- [ ] 反射是否可以用直接访问替代？
- [ ] 抽象层是否过多？

## ⚡ 参数验证铁律

### 标准验证流程

**步骤1: 源码确认**
- 查看参数定义和默认值
- 理解参数的真实含义
- 确认取值范围和边界

**步骤2: 小范围测试**
```csharp
// 测试不同参数值
PopText(text, 1f);    // 很慢
PopText(text, 10f);   // 默认速度
PopText(text, 50f);   // 很快
PopText(text, 100f);  // 极快
```

**步骤3: 效果记录**
- 记录不同参数的视觉效果
- 确定最优参数值
- 在代码中添加注释说明

**步骤4: 文档化**
- 记录到记忆文件
- 更新相关文档
- 分享给团队成员

### 参数误解案例分析

**气泡速度参数**:
- **常见误解**: speed越小越快
- **源码真相**: speed越大越快（控制动画速度）
- **错误用法**: `PopText(text, 0.1f)` // 实际是超级慢
- **正确用法**: `PopText(text, 50f)`  // 5倍速

## 🎯 三层持久化开发方法论 【核心守则】

### 💎 原则声明
**"每完成一个重要任务，必须完成三层持久化记录，一个都不能少！"**

这是项目的最高优先级守则，确保知识完整传承和团队高效协作。

### 📋 三层持久化体系

#### 第一层：Git提交记录 📦
**目的**: 代码变更历史和可追溯性
**时机**: 功能完成，代码稳定后立即执行
**要求**:
- ✅ **详细提交信息**: 清晰描述问题和解决方案
- ✅ **技术细节记录**: 记录关键代码变更和设计决策
- ✅ **影响范围说明**: 明确修改的文件和功能模块

**提交信息模板**:
```
<type>: <功能简述>

🎯 核心问题：
- 问题1：具体描述
- 问题2：具体描述

🔧 解决方案：
- 解决方案1详细描述
- 关键代码变更记录

📊 影响范围：
- 性能改善指标
- 用户体验提升
```

#### 第二层：项目文档更新 📊
**目的**: 项目级状态跟踪和团队协作
**时机**: 功能验证完成后，与其他功能集成前
**要求**:
- ✅ **TODO清单更新**: 标记任务完成状态，记录关键信息
- ✅ **CHANGELOG记录**: 详细的问题分析和解决方案记录
- ✅ **README更新**: 版本信息和主要改进说明
- ✅ **版本管理**: 确保版本号正确反映功能状态

#### 第三层：技术设计文档 📖
**目的**: 完整的技术实现细节和知识传承
**时机**: 重要功能或复杂问题解决后，项目稳定时
**要求**:
- ✅ **完整的问题分析**: 根本原因分析和技术挑战
- ✅ **详细的实现方案**: 技术架构和代码逻辑
- ✅ **代码变更记录**: 每个文件的具体修改和示例代码
- ✅ **性能影响分析**: 量化的改善指标和用户体验数据
- ✅ **经验总结**: 关键学习、最佳实践、技术债务清理

**技术文档结构**:
